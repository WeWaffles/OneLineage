## Build / install

```bash
JAVA_HOME=/c/Users/Avett/android/jdk-17.0.21+9 ANDROID_HOME=/c/Users/Avett/android bash build_apk_windows.sh
/c/Users/Avett/android/platform-tools/adb.exe install -r 'C:\Users\Avett\Documents\GitHub\OneLineage\out\OneLineage.apk'
```

- Return app: `JAVA_HOME=... ANDROID_HOME=... bash tools/oneui_return/build.sh` (writes `assets/OneUIReturn.apk`).
- Bridge: `ANDROID_HOME=... bash native/build_native.sh`.
- **Before installing OnePixel, check that adb is on One UI.** `pm list packages | grep -c sec.android.app.launcher` should print 1. If `nexuslauncher` shows instead, adb is on PixelOS and installs go into the guest.
- In Git Bash, set `MSYS_NO_PATHCONV=1` for adb commands with `/data/...` paths.
- adb's shell is One UI's (host) filesystem. `pm`/`cmd`/`dumpsys` talk to whichever OS is running. To act inside the guest's filesystem, use `su -c 'nsenter -t <guest system_server pid> -m -- ...'`. The guest's system_server is the one whose `/proc/<pid>/ns/mnt` differs from `/proc/1/ns/mnt`. Shell `settings put` fails in the guest (AppOps NPE), and `cmd overlay fabricate` needs root inside the guest namespace.
- KernelSU sometimes drops Shell's root grant. The user fixes it by giving Shell superuser in KernelSU.

## Always-on display

- Works. Framework overlay (`tools/display_overlay/res/values/config.xml`): `config_dozeComponent` = SystemUI's DozeService, `config_dozeAlwaysOnDisplayAvailable` = true, `config_screenBrightnessDozeFloat` = 0.1. SystemUI overlay (`systemui/res/values/bools.xml`): `doze_display_state_supported` and `doze_suspend_display_state_supported` = true. Rebuild with `ANDROID_PLATFORM=android-34 ... bash tools/display_overlay/build.sh` (only android-34 is installed here).
- Screen off -> display state DOZE_SUSPEND, SF powerMode DozeSuspend; the user confirmed the clock shows. The panel floor is set through Samsung's LFD node (below).
- **1 Hz:** `/sys/class/lcd/panel/vrr_lfd` shows the allowed LFD range (`[result]` at the bottom) and `dmesg` logs changes. Awake the normal-scope floor is 10 Hz. One UI's AOD adds an `aod` client: `echo "client=aod scope=normal scalability=6" > vrr_lfd` -> 1-120 Hz, `scalability=0` clears it (syntax from the strings of `/vendor/bin/hw/android.hardware.lights-service.samsung`; the hex `0x%x %d %d` format is not it). `alpm`/`hlpm_mode` stay 0 in both OSes.
- `master_inner.sh` has a watcher that follows the guest event log `power_screen_state` ([0,..] off/doze, [1,..] on) and writes that client; log at `lineage_stage/data/ol_aod_lfd.log`. Verified in PixelOS: dozing = 1.0-120 Hz, awake = 10-120 Hz, same as One UI.
- The doze brightness in the log matched the manual level (~10 nits), so the 0.1 value may not apply. Tune if AOD is too dim or bright.

## SELinux enforcing + seccomp (works)

The guest used to run with SELinux permissive (`switch_to_lineage.sh` does `setenforce 0` for staging; `return_to_oneui.sh` restores 1) and every app had `Seccomp: 0` (zygote only installs its seccomp filter when SELinux is enforcing as it starts). Now: enforcing before zygote, every app process `Seccomp: 2`, `Seccomp_filters: 1`, zero enforced denials at boot. The OneLineage creator's advice was exactly this (enforcing + seccomp, "make a snapshot when you do that"; snapshots: tags `backup/before-mount-hiding`, `backup/before-selinux-enforcing`).

How it works (all in `assets/`):
- `master_prepare.sh` step 5b3 patches the live policy with `ksud sepolicy patch` (gone at the next boot). It must run there: from inside `master_inner.sh`'s pivoted root the command exits 0 and changes nothing. Statements that name a missing type are also silently ignored (exit 0), so check the real policy (`/sys/fs/selinux/policy`), as the step does.
- The guest runs PixelOS userspace against Samsung's policy, which lacks types PixelOS's context files use. Defined there: service types adbroot_service, horae_service, lineage_{globalactions,hardware,health_interface,livedisplay,profile,trust}_service, osense_service, vendor_audioserver_service, vendor_qrs_service (with `typeattribute ... service_manager_type`) and app domains esim_switcher_app, ifaa_app, mediashell_app, pen_app, updater_app. Without them servicemanager can't evaluate "add" and `system_server` dies creating LineageHardwareService ("SELinux denied for service"). To find missing types again: mount `system.raw` read-only and compare the `*_contexts` types with the strings in `/sys/fs/selinux/policy`.
- Plus 14 allow rules (guest daemons run as the `ksu` domain; keystore2_key, service_manager) and `permissive` for system_server, system_app, platform_app, priv_app as a safety net (SELinux itself stays enforcing; app domains such as untrusted_app/gmscore_app are fully enforced). Tightening those four is the open follow-up: empty that loop and see what breaks (enforced denials are rate-limited in the audit log, so go one domain at a time).
- Labels: staged files bound into the guest's system (`*_patched.*`, overlays, sysapps, secims, layers) are labeled `system_file` (step 5b2, not shell_data_file); `master_inner.sh` runs `restorecon -RF /data/app /data/dalvik-cache` with the guest's own file_contexts (apk_data_file etc.) right before zygote. Both were crashers (PermissionController "exactly one permissions manager; found []"; Play Store `dlopen failed: couldn't map`).
- Step 3c1 binds a modified `product_seapp_contexts` (one extra line `user=network_stack seinfo=default domain=network_stack type=radio_data_file`) because the guest runs the Google-signed NetworkStack, which PixelOS's mac_permissions maps to seinfo=default; otherwise zygote aborts it ("No match for app with uid 1073") and Wi-Fi/data have no network ("IpClient is not ready").
- `master_inner.sh` flips to enforcing and starts a watchdog: if the guest launcher process doesn't appear within 3 minutes it goes back to permissive (log: `lineage_stage/data/ol_selinux.log`). Opt out: create `lineage_stage/data/local/tmp/ol_permissive`.
- Gotchas: the guest and host SHARE one property store (a `setprop` from the host shell is seen in the guest, and `sys.boot_completed` can still be One UI's value). `nsenter -t <pid>` needs the guest's pid (system_server's `/proc/<pid>/ns/mnt` differs from `/proc/1/ns/mnt`); pids change every boot. The audit log rate-limits (`audit_rate_limit=5`), so "no denials" is weak evidence. `build_apk_windows.sh` sometimes fails with a missing `build/compiled_res.zip`: just rerun it.

## Safety rules learned (also in memory)

- The guest shares host daemons and partitions. Never bridge installd, artd, vold, recovery and similar services (`container-shares-host-daemons.md`).
- Keep the recovery/wipe stubs and the PDB stubs in services_patched.jar. Never stub onStart or signalInitDone in PDB (init timeout kills system_server).
- Never forward the host TEE gatekeeper; the guest uses the bridge's software one (`guest-gatekeeper-soft.md`).
- The bridge remaps One UI vs PixelOS AIDL codes (`aidl-code-mismatch.md`).
- The image's `/system/product` is an ABSOLUTE symlink to `/product`. From the host it lands in One UI's /product. Always use `$ROOTFS/product`.
- Guest /dev is a slave of the host's ("master:" in mountinfo), so binds there don't propagate back.
- After any guest storage crash, check the misc BCB (`guest-recovery-wipe.md`).
