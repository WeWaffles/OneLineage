## Build / install

```bash
JAVA_HOME=/c/Users/Avett/android/jdk-17.0.21+9 ANDROID_HOME=/c/Users/Avett/android bash build_apk_windows.sh
/c/Users/Avett/android/platform-tools/adb.exe install -r 'C:\Users\Avett\Documents\GitHub\OneLineage\out\OneLineage.apk'
```

- Return app: `JAVA_HOME=... ANDROID_HOME=... bash tools/oneui_return/build.sh` (writes `assets/OneUIReturn.apk`).
- Bridge: `ANDROID_HOME=... bash native/build_native.sh`.
- **Before installing OnePixel, check that adb is on One UI.** `pm list packages | grep -c sec.android.app.launcher` should print 1. If `nexuslauncher` shows instead, adb is on PixelOS and installs go into the guest.
- In Git Bash, set `MSYS_NO_PATHCONV=1` for adb commands with `/data/...` paths.
- adb's shell is One UI's (host) filesystem. `pm`/`cmd`/`dumpsys` talk to whichever OS is running. To act inside the guest's filesystem, use `su -c 'nsenter -t <guest system_server pid> -m -- ...'`. The guest's system_server is the one whose `/proc/<pid>/ns/mnt` differs from `/proc/1/ns/mnt`. Shell `settings put` fails in the guest (AppOps NPE), and `cmd overlay fabricate` needs root inside the guest namespace.
- KernelSU sometimes drops Shell's root grant. The user fixes it by giving Shell superuser in KernelSU.

## Always-on display

- Works. Framework overlay (`tools/display_overlay/res/values/config.xml`): `config_dozeComponent` = SystemUI's DozeService, `config_dozeAlwaysOnDisplayAvailable` = true, `config_screenBrightnessDozeFloat` = 0.1. SystemUI overlay (`systemui/res/values/bools.xml`): `doze_display_state_supported` and `doze_suspend_display_state_supported` = true. Rebuild with `ANDROID_PLATFORM=android-34 ... bash tools/display_overlay/build.sh` (only android-34 is installed here).
- Screen off -> display state DOZE_SUSPEND, SF powerMode DozeSuspend; the user confirmed the clock shows. The panel floor is set through Samsung's LFD node (below).
- **1 Hz:** `/sys/class/lcd/panel/vrr_lfd` shows the allowed LFD range (`[result]` at the bottom) and `dmesg` logs changes. Awake the normal-scope floor is 10 Hz. One UI's AOD adds an `aod` client: `echo "client=aod scope=normal scalability=6" > vrr_lfd` -> 1-120 Hz, `scalability=0` clears it (syntax from the strings of `/vendor/bin/hw/android.hardware.lights-service.samsung`; the hex `0x%x %d %d` format is not it). `alpm`/`hlpm_mode` stay 0 in both OSes.
- `master_inner.sh` has a watcher that follows the guest event log `power_screen_state` ([0,..] off/doze, [1,..] on) and writes that client; log at `lineage_stage/data/ol_aod_lfd.log`. Verified in PixelOS: dozing = 1.0-120 Hz, awake = 10-120 Hz, same as One UI.
- The doze brightness in the log matched the manual level (~10 nits), so the 0.1 value may not apply. Tune if AOD is too dim or bright.

## Safety rules learned (also in memory)

- The guest shares host daemons and partitions. Never bridge installd, artd, vold, recovery and similar services (`container-shares-host-daemons.md`).
- Keep the recovery/wipe stubs and the PDB stubs in services_patched.jar. Never stub onStart or signalInitDone in PDB (init timeout kills system_server).
- Never forward the host TEE gatekeeper; the guest uses the bridge's software one (`guest-gatekeeper-soft.md`).
- The bridge remaps One UI vs PixelOS AIDL codes (`aidl-code-mismatch.md`).
- The image's `/system/product` is an ABSOLUTE symlink to `/product`. From the host it lands in One UI's /product. Always use `$ROOTFS/product`.
- Guest /dev is a slave of the host's ("master:" in mountinfo), so binds there don't propagate back.
- After any guest storage crash, check the misc BCB (`guest-recovery-wipe.md`).
